# Invoice Reconciliation Platform

Python (pandas, FastAPI) + SQL (PostgreSQL / SQLite) backend that ingests invoice and payment
CSVs, cleans them, loads a 6-table relational schema, and runs 12 reconciliation rules.
All data is **synthetic** (generated by `app/generator.py`).

## Run it
```bash
python -m pip install -r requirements.txt
python -m pytest --cov=app            # 80 tests
python -m uvicorn app.main:create_app --factory --reload
# open http://localhost:8000/docs  ->  POST /data/generate?n=100000, then POST /reconcile, then GET /summary
```
PostgreSQL + Docker:
```bash
docker compose up --build                      # API on :8000, Postgres on :5432
TEST_DATABASE_URL=postgresql+psycopg2://recon:recon@localhost:5432/recon python -m pytest
```

## Design in one minute
- `generator.py`: builds N invoices + payments and injects anomalies into disjoint blocks, so the true answer is known.
- `cleaning.py`: strips/uppercases text, parses dates and amounts, rejects unusable rows (counted, not silently dropped).
- `db.py`: 6 tables: vendors, customers, tax_rates, invoices, payments, exceptions. Bad references are stored as NULL FKs, then reported.
- `rules.py`: 12 vectorised rules (8 data-quality, 3 invoice-vs-payment, 1 orphan payment).
- `pipeline.py`: load reference data -> ingest (clean, resolve keys, insert) -> reconcile (run rules, write exceptions).
- `main.py`: 8 endpoints: /health, /data/generate, /data/upload, /reconcile, /summary, /exceptions, /invoices/{id}, /trends.

## Rules
MISSING_VENDOR, DUPLICATE_INVOICE, NON_POSITIVE_AMOUNT, TAX_MISMATCH, TOTAL_MISMATCH, FUTURE_DATED,
DUE_BEFORE_ISSUE, INVALID_CURRENCY, UNPAID_OVERDUE, OVERPAID, PARTIALLY_PAID_OVERDUE, ORPHAN_PAYMENT.

## Known limits
- Data is synthetic; anomalies are injected, so "100% detection" means the rules match the injected definitions, not real-world recall.
- Money is stored as NUMERIC(14,2) and compared with a 0.02 tolerance; no currency conversion.
- No authentication; CORS allows only http://localhost:4200.
